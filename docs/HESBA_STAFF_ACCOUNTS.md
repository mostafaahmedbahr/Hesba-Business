# الحسابات الفرعية (Staff Accounts)

## الفكرة

صاحب المحل ينشئ حساب دخول لموظف من:
**القائمة / المزيد → الحسابات الفرعية → إضافة موظف**.

الحساب الفرعي:

- يملك أربع عمليات فقط: **بيع جديد / شراء مخزون / مرتجع جديد / مصروف جديد**.
- **لا يرى**: الداشبورد، التقارير، الأرباح، قائمة المبيعات، قائمة المصروفات،
  الحسابات والذمم، الموردين، الأقسام، إدارة المنتجات، لوحة التحكم.
- **لا يستطيع**: إضافة أو تعديل أو حذف منتج، إضافة عميل/مورد/ذمة،
  تعديل أو حذف أي سجل أدخله (يستطيع الإضافة فقط).
- البيع الآجل واختيار العميل مخفيان تمامًا في حساب الموظف (منع إنشاء ذمم).
- إذا أوقف الصاحب الحساب، يُطرد الموظف من التطبيق فورًا وتُمنع كل عملياته.

> الحد الأدنى المسموح بالقراءة داخل الفورم فقط: أسماء المنتجات (لبيع/الشراء)،
> الفواتير والمرتجعات السابقة (لاختيار فاتورة المرتجع والتحقق من الكمية)،
> واسم المحل ونوع النشاط. إجماليات الفواتير مخفية في واجهة المرتجع.

## النموذج التقني

- `users/{staffUid}`:
  - `role: 'staff'`
  - `ownerId`: uid صاحب المحل
  - `shopId`: نفس shopId صاحب المحل
  - `isActive`: للتفعيل/الإيقاف
- الاشتراك **محسوب على صاحب المحل**؛ الموظف ليس لديه اشتراك منفصل.
- البيانات التي يسجلها الموظف تُحفظ بـ `shopId` المحل نفسه، فتظهر لصاحب المحل
  في التقارير والداشبورد بشكل طبيعي، مع `ownerId = uid الموظف` لأغراض التدقيق.

## ملفات مهمة

- `lib/features/staff/` — إدارة الحسابات + شاشة الموظف.
- `lib/core/services/user_role_service.dart` — تحديد الدور وتوجيه المستخدم.
- `lib/core/router/app_router.dart` — حظر مسارات الموظف.
- `firestore.rules` — منع القراءة والكتابة على مستوى قاعدة البيانات (الحارس الحقيقي).
- `firestore.indexes.json` — فهرس استعلام الحسابات الفرعية.

## نشر إلزامي

بدون نشر القواعد الجديدة، الحماية على مستوى الخادم لن تُفعّل:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

## استكشاف خطأ `permission-denied`

لو الموظف بيضيف ومبيقدرش، افتح شاشة الموظف واضغط أيقونة الدرع
(تشخيص الصلاحيات) — هتظهر: الدور، `ownerId`، `shopId`، حالة التفعيل،
وحالة اشتراك صاحب المحل.

القاعدة بقت تتعافى من غياب `ownerId`: لو الحقل ناقص، بتقرأ صاحب المحل
من `shops/{shopId}.ownerId`. المهم إن `role` لازم يكون `staff` بالظبط
و`isActive: true` و`shopId` موجود.

بعد أي تعديل في القواعد لازم تعيد النشر:
```bash
firebase deploy --only firestore:rules
```

## الاختبارات

```bash
cd rules_tests
firebase emulators:exec --only firestore --project hesba-business "npm test"
```

اختبارات `staff.test.js` تغطي: creation بصلاحية محدودة، منع تصعيد الصلاحية،
منع قراءة البيانات المالية، السماح بأربع عمليات الإضافة فقط، ربط الاشتراك
بصاحب المحل، ومنع الحساب الموقوف.
