# استعادة نسخة احتياطية لتطبيق حسبة (بدون Blaze)

السكربت ده بيرجّع نسخة JSON المصدّرة من التطبيق إلى Firestore بصلاحيات
**Admin SDK** من جهاز الكمبيوتر.

**مجاني 100%**: مش محتاج Cloud Functions، ومش محتاج خطة Blaze، ومش محتاج تغيير
`firestore.rules`. كل اللي محتاجه مفتاح حساب خدمة (Service Account) ومشروعك.

## لازم Admin SDK؟ نعم

قواعد Firestore الحالية تمنع الاستعادة من التطبيق العادي:

- `suppliers` / `persons` / `debts` / `debts/{id}/payments` تشترط
  `createdAt == request.time` عند الإنشاء، فأي تاريخ قديم يُرفض.
- `sales` / `expenses` / `returns` تسمح بالتعديل للأدمن فقط، فـ `merge` على
  مستند موجود يُرفض من حساب صاحب المحل.

السكربت يستخدم حساب خدمة فيتجاوز القواعد **بشكل مشروع** ومع ذلك لا يغيّر
`firestore.rules` نفسه.

## الطريقة الأسهل على Mac: ملف `restore.command` 🎯

```bash
cd tool/restore_backup
chmod +x restore.command      # مرة واحدة بس
```

بعدين **اضغط مرتين** على `restore.command` في Finder (أو اسحب ملف النسخة عليه).
الملف بيطلب منك ملف النسخة بنافذة اختيار، بيثبّt التبعيات لو مش موجودة،
بيعمل معاينة، وبعدين بيطلب منك تكتب `RESTORE` قبل ما يكتب أي حاجة في Firestore.

لو مفيش مفتاح حساب خدمة، بيفتح لك صفحة **Service accounts** في المتصفح ويطلب
منك تحفظ الملف باسم `serviceAccount.json` جنبه. المفتاح مش بيظهر في الشاشة
ومستبعد من Git.

الأسئلة الشائعة:
- عايز تستخدم مشروع تاني؟ `HESBA_PROJECT=other-id ./restore.command`
- عايز تختبر على الإموليتر الأول؟ شغّل `firebase emulators:start --only firestore`
  واستخدم الأوامر اليدوية في القسم اللي تحت بـ `--emulator`.

## 1) تصدير النسخة من التطبيق

افتح **المزيد ← إدارة المتجر ← النسخ الاحتياطي ← إنشاء نسخة احتياطية**.

التطبيق يكتب ملفين في مجلد المستندات الخاص به:

```
hesba_<shopId>_<timestamp>.json       (للقراءة والفحص)
hesba_<shopId>_<timestamp>.json.gz    (أصغر حجماً)
```

زر **مشاركة / حفظ النسخة** يرسل الملف إلى Drive أو واتساب أو أي تطبيق تختاره.
ابعته لنفسك أو للكمبيوتر اللي هتشغّل عليه السكربت.

لجهاز Android قابل للتنقيح (debug) يمكنك أيضاً سحب الملف مباشرة:

```bash
adb shell run-as com.zerobugs.hesba \
  cat files/backups/hesba_<shopId>_<timestamp>.json > backup.json
```

لو ظهر تنبيه **"جزء من البيانات من كاش الجهاز"** أعد التصدير وأنت متصل.

## 2) تجهيز السكربت

```bash
cd tool/restore_backup
npm install
```

ضع مفتاح حساب الخدمة في أحد مكانين:

- ملف `serviceAccount.json` بجانب السكربت (مستبعد من Git)، **أو**
- متغير البيئة `GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json`

> لا تستخدم مفتاح حساب الخدمة في التطبيق ولا ترتكه في Git.

## 3) المعاينة ثم الاستعادة

```bash
# معاينة بدون أي كتابة — راجع الأعداد قبل التنفيذ
node restore.js backup.json.gz --dry-run

# تنفيذ فعلي
node restore.js backup.json.gz --yes

# تحديد المشروع صراحةً
node restore.js backup.json --yes --project=hesba-business
```

خيارات مفيدة:

- `--skip=admin_settings,subscription_requests` لتخطي مجموعات معينة
  (مفيد لو هتمسح بيانات المحل بس ومش عايز تلمس إعدادات المنصة).
- `--dry-run` لا يكتب أي شيء، لكنه يتحقق من الصيغة والمسارات والتواريخ.
- `--emulator` يوجّه الكتابة إلى Firestore Emulator على `127.0.0.1:8080`
  بدون مفتاح خدمة — استخدمه للتجربة الأولى قبل لمس بيانات الإنتاج:

```bash
firebase emulators:start --only firestore
node restore.js backup.json.gz --yes --emulator --project=demo-hesba
```

## 4) سيناريو الاختبار اللي اقترحته

> **ابدأ بالإموليتر** قبل أي مسح حقيقي. لو الاستعادة اشتغلت هناك، كرّر نفس
> الخطوات على الإنتاج وأنت مطمئن.

1. افتح التطبيق واعمل نسخة احتياطية، واحتفظ بالملف خارج الجهاز.
2. امسح مستندات المحل من Firebase Console
   (products / sales / returns / expenses / debts / persons / ...).
   **لا تحذف مستخدمي Firebase Auth** — حسابات المصادقة مش داخل النسخة،
   وحذفها هيخليك مش قادر تسجّل الدخول للتحقق.
3. شغّل `--dry-run` وراجع العدد.
4. شغّل الاستعادة بـ `--yes`.
5. افتح التطبيق من جديد: المبيعات والمصروفات والتقارير والذمم والمخزون
   لازم ترجع بنفس تواريخها وأرقامها.

## ملاحظات مهمة

- الكتابة تتم بنفس `doc id` الأصلي + `merge: true`، فإعادة تشغيل السكربت
  مرتين **لا يعمل سجلات مكررة** ولا يغيّر `createdAt`.
- `merge` لا يحذف حقول أُضيفت بعد التصدير، ولا يحذف مستندات حُذفت بعده؛
  الاستعادة الكاملة بمعنى "إرجاع ما كان موجوداً"، مش "مرآة طبق الأصل".
- المصفوفات (مثل `items` في الفاتورة) تُستبدل كاملة — وهذا مطلوب عشان
  بيانات الفاتورة ما تختلطش.
- النسخة فيها **روابط Cloudinary** فقط؛ لو الصور نفسها ضاعت لازم ترفعها
  منفصلة. تنزيل الصور داخل الأرشيف ممكن يتضاف لاحقاً.
- بيانات الجهاز المحلية (سجل النشاط والتذكيرات والثيم) محفوظة في
  SharedPreferences وليست داخل النسخة؛ استعادتها على جهاز جديد تحتاج نقلها
  بشكل منفصل.
- تشغيل الاختبارات المحلية للـ transformer (بدون اتصال بـ Firebase):

```bash
npm run check
```
